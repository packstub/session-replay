# Changelog

All notable changes to `packstub/session-replay` are documented here.

## Unreleased

### Changed

- **Docs.** The README opens with a banner and an animation of a replay: a rage click, the server error's details and "Open in logs". Docs sync to packstub.dev on every change to `docs/` (`docs-sync.yml`).

## 1.0.0 — 2026-10-22

### Added

- **`SessionReplay.send()`, for a "report a problem" button.** `SessionReplay.send('Wrong total on the invoice')` adds a `report` marker at that moment and uploads what the browser holds. In mode `on_error` the kept window goes up right away, without the `on_error.ask` question (pressing the button is the answer), and the tab records from then on; a tab that declined the question sends nothing. The promise resolves once the upload went through or was given up on, to whether anything was sent. The `report` marker type keeps what people reported apart from the app's own `mark()` calls (`custom`): `ReplaySession::reported()` finds those recordings, the built-in list filters and badges them (new strings `viewer.reported`, `viewer.reported_badge` and `player.types.report` in all five languages), and a `ReplayReported` event with the recording and the marker is dispatched once per report, to tell support with a link ([#39](https://github.com/packstub/session-replay/issues/39)).
- **The impersonator as a model.** `SessionReplay::impersonatorUsing()` and the directive's `impersonator` option may return the impersonator's model instead of a key: its morph class is stored in the new `replay_sessions.impersonator_type` column (run `php artisan migrate`), `$session->impersonator` loads them and the player page names them by `viewer.user_label`. A key works as before, stored alone. A recording keeps its impersonator's type: an upload signed for the same key of another model is refused ([#40](https://github.com/packstub/session-replay/issues/40)).
- **A `ReplaySession` policy authorizes the data routes too.** Without a `viewSessionReplay` gate, `SessionReplay::check()` now asks a policy registered for `ReplaySession`: `viewAny` for the list, `view` for a recording, the player page and its manifest, chunks and stylesheets. With Filament Shield's generated policy the watch page's player no longer says "You are not allowed to watch this recording" until a delegating gate is added. A gate that is defined still decides ([#41](https://github.com/packstub/session-replay/issues/41)).
- **`session-replay:session`, a browser event when the recording changes.** Dispatched on `window` whenever the id `SessionReplay.sessionId()` returns changes (a recording starts, a new one replaces it, it stops), with `event.detail.id`, so a front-end error tracker can tag its events with the recording without polling ([#43](https://github.com/packstub/session-replay/issues/43)).
- **`SESSION_REPLAY_RETENTION_DAYS`** sets `retention.days`.
- **`on_error.ask = 'toast'`.** The question can sit in a card at the bottom corner of the viewport instead of a modal dialog: the page stays usable, nothing takes the focus, Escape is left to the page. A question left unanswered for `on_error.ask_timeout_seconds` (60; `0` waits for ever) counts as "Don't send", like the dialog's own "no". `true` (or `'dialog'`) keeps the dialog; the recorder config now carries `ask` as `false`, `'dialog'` or `'toast'`.
- **Autoplay for the player.** `viewer.autoplay` (off by default) starts a replay as soon as the player is ready, from the linked moment when the URL has `?t=` or `?at=`; `<x-session-replay::player :autoplay="true" />` sets it for one player, and the Filament watch page follows the config.
- **`on_error.ask_again`.** A "no" to the `on_error.ask` question (or a toast left unanswered) left the tab alone until its session ended. With `ask_again = true` the tab keeps a window and asks again on the next trigger, at most once per window (`buffer_seconds`), so a burst of errors asks once. Off by default: nothing changes without it.
- **`on_error.max_buffer_mb`.** The most the window of mode `on_error` may take in memory (5 MB of events as the recorder estimates them, 1 to 50) was fixed in the recorder; a page that changes a lot reaches it before `buffer_seconds` and shrinks the window to its newest snapshot.
- **Marker details in the player, and a way from a server error to its log lines.** A click on a marker now also opens its details under the list: what the index stores about it, row by row (a server error's exception, status, method, path and message when captured; a failed request's status and URL; a console marker's arguments; where a rage click happened; a page's URL and title), with **Copy link to this moment** for that marker's second. When Laravel reports an exception during a recorded request, the report gets an id (a ULID) that the `error` marker carries in its payload as `report` and that goes into `Context` as `session_replay_report` before Laravel logs the exception, so the log lines and the error tracker's event of exactly that exception carry it too; the details show it with **Copy report id**. `SessionReplay::logUrlUsing(fn (ReplayMarker $marker) => ...)` says where a marker's log lines are read (Log Viewer's `?query=`, Telescope, Sentry), and the details then offer **Open in logs**; the manifest carries it as `logUrl` per marker. New strings `player.details.*` and `player.fields.*` in all five languages.
- **A marker where pages the app does not record were skipped.** A `wire:navigate` session that passes through an `except` or `except_routes` page keeps one recording with a gap in it, which showed as the last page frozen until the next recorded one appeared. One `navigation` marker now sits at the start of the gap, "Page not recorded", with how long the pages took (payload `skipped: true`, `durationMs`) and nothing about which pages; the player draws the gap as a hatched band on the timeline and names it in the viewer's language, and the recording's page count leaves it out. A page that starts a new recording (another person or workspace, idle past `idle_minutes`) gets no marker, since the pages before it belong to no replay.
- **`privacy.unmask_text_selector` for `mask_all_text`.** Layout-only mode blanked the app's own menus, headings and button captions too, which made replays hard to follow. Text inside `[data-replay-unmask]` (the default selector) now stays readable in that mode, text attributes included, unless `mask_text_selector` matches it; input values are never affected. Without `mask_all_text` it does nothing.
- **Failed requests and page views of apps without Livewire.** An Inertia, Vue, React or axios app had no markers for a failed API call or a client-side page change. The recorder now marks same-origin `fetch` and `XMLHttpRequest` requests answered with a status at or above `capture.requests` (default `500`), or not at all, as `request` markers with method, path, status and duration (never headers or bodies); in mode `on_error` they upload the window like a failed Livewire request. `history.pushState` and the back button add `navigation` markers. `capture.requests = false` turns the requests off.
- **Server errors on the replay, and a log link that opens at the moment.** A replay showed a failed request only from the browser's side, and the log context's link opened the recording at its start. An exception Laravel reports during a recorded request is now an `error` marker (`source: server`) with the exception's class, status, method and path; the message only with `capture.server_errors = 'message'`, its URLs redacted. Only the request's own person's recording gets it; in mode `on_error`, where the recording is usually stored after the failed request, it waits in the cache for the first batch. A new Context key, `session_replay_moment`, links to the replay with `?at=` and the request's time, and the player opens such a link three seconds before it. `capture.server_errors = false` turns the markers off.
- **Copy link to this moment.** A button under the player's controller copies the page's URL with `?t=` at the second the replay is at, to paste into a ticket or a chat; it opens only for someone the gate lets in. `<x-session-replay::player :copy-link="false" />` hides it. New strings `player.copy_link` and `player.link_copied` in all five languages.

### Changed

- **Config keys that name their unit.** `idle_timeout` is now `idle_minutes`, `flush_interval` (milliseconds) is `flush_seconds` (default `5`, fractions allowed), `on_error.ask_timeout` is `on_error.ask_timeout_seconds` and `ingest.throttle` is `ingest.requests_per_minute`; `flush_seconds` moved up to the recording settings. A published config with the old names keeps working, the old key standing in for the new one unless the new one is set too; `config()->set()` at runtime needs the new names ([#42](https://github.com/packstub/session-replay/issues/42)).
- **`viewer.guard` sets the viewer's login too.** A plain `auth` in `viewer.middleware` now asks that guard (`auth:admin`), so setting the guard alone is enough; a middleware list that names a guard itself is left alone.
- **Properties are capped at 4 KB.** What `propertiesUsing()` and the directive's `properties` give travels in every recorded page's token, which is signed, not encrypted; larger properties are left out and a warning is logged. The docs now say that the token can be read in the page's source.
- **A stylesheet is served only to a recording that points at it**, as a shared snapshot already was: a stylesheet may carry a workspace's own theme. Recordings from before stylesheets were referenced (1.0.0-beta.5 and earlier; a shared snapshot they point at changes nothing) are served by hash as before.
- **The classes the package wires itself are marked `@internal`** (`BatchIngester`, `ServerErrors`, the controllers, the middleware, `ReplayStorage::toGzip()` and `inflate()`); the models, `ReplayStorage`'s paths and disk, the events, the facade and the Blade component are the public API.
- **Docs.** Recording says that the Filament plugin detects Packstub's Account Switcher for the impersonator on its own.
- **Methods that are not public API are marked `@internal`** on `SessionReplayManager` (`shouldRecordFor()`, `isExcluded()`, `sharesSnapshots()`, `logUrlFor()`, `idleMinutes()`, `scriptUrl()`, `scriptPath()`, `device()`) and on `ContextToken`; the facade's docblock lists the public ones, `enabled()`, `user()`, `mode()`, `consent()` and `viewer()` added.

- **The recorder bundle runs once per tab with `wire:navigate`.** Livewire runs every script of the new page's body again on each `wire:navigate`, so the browser evaluated the whole recorder on every page only for it to find itself already running. Its script tag now carries `data-navigate-once`; the config next to it still runs on every page, which is how the recorder checks each one.
- **An index on `replay_sessions` (`tenant_type`, `tenant_id`, `started_at`)** for a workspace's list, newest first. Run `php artisan migrate` (or publish the migrations again with `run_migrations` off): `add_tenant_started_at_index_to_replay_sessions_table` adds it to an existing install, and does nothing where `create_replay_sessions_table` already made it.
### Fixed

- **A published config's old key names were ignored on a normal boot.** The old names (`idle_timeout`, `flush_interval`, `on_error.ask_timeout`, `ingest.throttle`) were read under the new ones after Laravel had merged the package's defaults in, by when the new keys were already there with their defaults, so the published values were dropped unless the config was cached. They are read before the defaults now, and the config test boots the provider the way an app does.
- **Times from the browser are stored in the app's timezone.** A recording's `started_at`, `last_activity_at` and every marker's moment were built as UTC and stored as such next to `created_at` in `app.timezone`, so in an app outside UTC the manifest's marker offsets were off by the timezone's offset (the player sought hours away from a marker), a recording looked finished while live, `?at=` links from the log context opened at the wrong moment and the prune window and the list's date filters mixed the two.
- **A report button pressed in a loop no longer floods support.** `ReplayReported` is dispatched for the first `report` marker of a recording, at most once a minute per recording; every marker is still stored and listed. A batch of two hundred crafted report markers used to dispatch two hundred events.
- **The recorder obeys the server's "stop" with the daily limit.** The daily limit answers 429 with `stop: true`, and the recorder retried every 429 before reading the answer, so a tab past `ingest.daily_mb` kept retrying its batches, and new ones, for the rest of the day. A stop is also remembered in the tab now (`sessionStorage`, until the session idles out or the person changes): after the size limit or a refused upload the next page loads used to start recording again, upload a snapshot and be refused again.
- **The upload pace recovers after a throttled minute.** The flush interval doubled on every 429 and never came back, so one busy minute left the tab uploading once a minute for its life, with up to a minute of events on the unload request alone.
- **What waits for a server that is away is bounded.** Batches queued while uploads fail no longer pile up raw in memory for as long as the outage lasts: past forty waiting batches the newest are dropped and the recording is cut there.
- **A hidden tab no longer loses a large batch.** Hiding a tab sent what the buffer held as one uncompressed keepalive request, like a closing page, so a snapshot of a large page went up uncompressed, could exceed `ingest.max_batch_kb` and was lost. A hidden tab now keeps the usual path (gzip, split, retries) for anything keepalive cannot carry; a closing page sends as before, through `sendBeacon` where `fetch` ignores `keepalive` (Firefox before 133).
- **The `on_error.ask` question goes away with the recording it asks about.** A question still up when the recording restarted (`wire:navigate` to another workspace, the person changed) or stopped stayed on screen, its answer went nowhere, and after `consent(false)` the tab asked nothing until it was answered.
- **`on_error.max_buffer_mb` measures what it bounds.** Every mutation counted as 300 characters whatever its size, so a page that polls a long table could hold far more than the limit while a question was up. A mutation that changes a lot is measured now.
- **A failed Livewire request's URL is redacted** like every other URL in a recording (`privacy.redact_query`).
- **`SessionReplay.send()` resolves to whether the server took the upload**, not to `true` after a batch was given up on.
- **The player reads whole without `data-labels`.** An element mounted by hand, without the Blade component's strings, threw on the first marker click (the details' field names and buttons had no English defaults) and labelled a skipped page "undefined". The English strings now cover every key of `lang/en/player.php`, and a test keeps them in step. `mount()` also accepts `autoplay`, the spelling of the config key and the component prop, next to `autoPlay`.
- **A misspelt `consent` or `mode` no longer records more than intended.** Any value other than the exact `opt-in` meant `always`, so `SESSION_REPLAY_CONSENT=optin` recorded everyone without asking, and any mode other than `on_error` uploaded every tab. The usual spellings (`opt_in`, `on-error`, any case) are now read as what they mean, and anything else as the stricter choice, `opt-in` or `on_error`, with a warning in the log naming the value ([#38](https://github.com/packstub/session-replay/issues/38)).
- **A list in a published config replaces the default list, whichever list it is.** Only some lists were replaced as a whole; the others were merged index by index, so `on_error.triggers = ['custom']` came out as `['custom', 'request']`, and `privacy.redact_query = []` or `except_routes = []` kept every default. Every list a published config sets now replaces the default's.
- **The replayed cursor no longer waits in the top left corner.** rrweb draws its cursor at the replay's top left until the first mouse or touch event, so a replay that starts without one (a visitor who reads before moving the mouse, a page reached by keyboard) showed it there. The player now shows the cursor from the first event that places it.
- **`mask_all_text` and `data-replay-mask` mask more of what the page says in attributes.** The caption of a submit button a script changed after the page loaded (`value`, a changed attribute names only the element), the `content` of a `<meta>` tag (a profile page's description), a `download` file name and an option's `label` stayed readable; they are masked now wherever the text around them is.
- **Pruning stylesheets a pinned recording does not need.** One old pinned recording kept every stylesheet last seen since it started, so an app that pins recordings kept every CSS build for good. A batch now records which stylesheets its recording points at (in `replay_session_assets`, next to the shared snapshots; a stylesheet still to be uploaded included, so the first recording of a new CSS build keeps it too), and `session-replay:prune` keeps a stylesheet only while a recording that is left points at it. Recordings from before this point at nothing: while a pinned one of those is left, stylesheets last seen since it started stay, as before.
- **No replay link in the log lines of a page the app does not record.** The recording's cookie stays set while a tab visits an `except` or `except_routes` page inside a recorded session, so that page's log lines carried `session_replay` and a link to a replay that shows nothing of it, and an exception there became an `error` marker on the recording. Once the route is matched, such a request now has none of the Context keys and raises no marker. Livewire's update requests from that page keep them: their path is not the page's. `SessionReplay::isExcluded($request)` is the check (`@internal`: the Filament package and the middleware share it).
- **Pages the app does not record are not recorded when reached with `wire:navigate` either.** `except`, `except_routes`, `recordWhen()` and the Filament plugin's own rules (its Sessions pages, `record()`) only kept the recorder off pages loaded in full: with `wire:navigate` the recorder of an earlier page kept going on them. The recorder now reads its config again on every page Livewire swaps in. A page without one is not recorded: no snapshot, events, markers or console messages, including those during the swap to it and away from it, until a page that is recorded; `SessionReplay.isRecording()` is `false` there. Each page's signed token is used from then on, and a page signed for another person, workspace or impersonator (a tenant switch with `wire:navigate`) starts a new recording, as a page load does; before, the visit was filed in the recording of the page the tab started on. A page's `snapshots.share` setting now applies to the snapshots taken on it.
- **Hidden and file inputs are masked in every case.** `privacy.mask_all_inputs` used rrweb's list of input types, which leaves out `hidden` and `file`: a value a script writes into a hidden input after the page loaded (Livewire, Alpine, Filament's `Hidden` field) and the name of a chosen file (`C:\fakepath\passport.pdf`) went out in clear. Inputs are now masked by tag, every type included; checkboxes and radios keep their checked state. Hidden and file inputs are masked even with `mask_all_inputs` off, like passwords.
- **`mask_all_text` and `data-replay-mask` mask text in attributes too.** rrweb masks text nodes only, so `alt`, `title`, `aria-label`, `placeholder` and a submit button's caption stayed readable (an avatar's "Avatar of Jane Doe"). They are now masked wherever the text around them is. With `mask_all_text` the `navigation` markers leave the page title out, and a rage-click on a button whose caption holds masked text is named by its tag only.
- **URLs in errors and console messages are redacted everywhere.** Promise rejections, `console` markers and the console plugin's own events (which repeat uncaught errors with their stack frames) skipped `privacy.redact_query`. URLs in `srcset`, `poster`, `ping` and `xlink:href` are redacted too.
- **A kept window survives a reload while the server hangs, and leaves when it should.** In mode `on_error` the window was kept in IndexedDB only once its upload failed; a server that is down often answers only after half a minute, and a reload before that lost the window. It is now kept as it goes up. Leftover windows (too old, kept for another person) were swept only by a recorded page that was not buffering: every page load now sweeps them, withdrawing consent removes every kept window of the origin, and a recording the server stops removes what its earlier pages kept.
- **A stylesheet whose upload failed is tried again.** Its text was dropped after the batch anyway, and pages using it replayed unstyled; it now goes again after the next batch.
- **Smaller fixes in the recorder.** A tab that is not sampled no longer sets the log-context cookie (log lines named a recording that never comes). The closing upload counts the whole request against the 64 KB keepalive limit, not only the events, and a failed one is no longer recorded as an error of the app. A tab idle past `idle_minutes` starts a new recording on its next `wire:navigate` page, as on a page load. The `on_error.ask` answer applies only to the recording it asked about.
- **A `visibleUsing()` rule with `orWhere()` no longer shows recordings from outside the list's scope.** `SessionReplay::visibleTo()` called the app's closure on the query itself, so `$query->where('user_id', $id)->orWhereNull('user_id')` (own recordings or guests') also matched rows that the query had already ruled out: other workspaces in a Filament panel scoped to its tenant, and the built-in list's filters. The rule now runs as one group of its own (`where(fn ($query) => ...)`), so it can only narrow.
- **Two first batches of a recording arriving at once no longer fail.** On Postgres the second one answered 500, and on MySQL the two could deadlock. The recording's row is now created without a transaction or a lock, the second upload loads the row the first one made, and `ReplaySessionStarted` is dispatched once, with the recording's first stored batch. The second upload is checked against the recording's person, impersonator and workspace like any later batch.
- **A batch that fails half way is stored in full when the browser retries it.** The chunk row, the markers, the counters and the shared-snapshot references were separate writes, so an error after the chunk row made the retry answer "duplicate" and that batch's markers and counts were lost. They are now written in one transaction on `storage.connection`. Two copies of a batch stored at the same moment answer "duplicate" instead of 500. The last activity and the worst vitals are compared by the database, so batches stored at the same time never move them back.
- **A stylesheet with the same content as a shared snapshot is served.** The stylesheet upload saw the hash stored (as a snapshot), stored nothing and answered as if it had, while the viewer only serves stylesheets: the page replayed unstyled for good. The stored snapshot, whose bytes were checked against the hash when they arrived, now counts as a stylesheet too; recordings that point at it as a snapshot still get it, and `session-replay:prune` keeps it while one does.
- **A shared snapshot sent again late in its day is no longer pruned before its batch arrives.** An upload moved the snapshot's last-seen date only when it was over a day old, while `session-replay:prune` deletes unreferenced snapshots last seen more than a day ago, so the grace could shrink to minutes. The date now moves when it is over an hour old.
- **Out-of-range numbers from the browser no longer fail an upload on Postgres or MySQL.** Viewport sizes, vitals, event counts and times are kept inside what the columns hold (Postgres has no unsigned columns), negative times and counts are ignored, and the counters stop at the largest integer instead of overflowing.
- **A session id sent in upper case is stored in lower case.** Postgres hands a uuid back in lower case, so the chunk files filed under the upper-case spelling were not found by the viewer or deleted with the recording on a disk that tells the cases apart.
- **A field sent as a list answers 422 (or 401 for the token) instead of 500.** `session[]`, `hash[]`, `token[]`, `meta[]`, `events[]` and `content[]` on the upload routes, and `?user[]=` and the other filters of the built-in list (ignored there), threw "Array to string conversion".
- **Rotating `APP_KEY` no longer stops every open tab from recording.** A recorder's token is accepted when it was signed with the current key or one of `app.previous_keys` (Laravel's key rotation, `APP_PREVIOUS_KEYS`); new tokens are signed with the current key.
- **The player no longer piles up in a panel with `wire:navigate`.** The player's script ran again on every watch page, each run added another `livewire:navigated` listener, and every player added a window `resize` listener that was never removed, so every replay watched in the tab stayed in memory with all its events. The script tag now has `data-navigate-once`, the script registers its listeners once per tab, and on `livewire:navigating` each player is paused, destroyed and its listeners removed; the next page's players are mounted on `livewire:navigated`. `SessionReplayPlayer.unmount(element)` stops one by hand.

## 1.0.0-beta.5 — 2026-10-07

### Changed

- **A `wire:navigate` page is recorded as a snapshot, like a page load.** Livewire replaces the whole page body on `wire:navigate`, which rrweb recorded as one change adding every node of the new page. The recorder now pauses on `livewire:navigating` and starts again on `livewire:navigated` (or after five seconds if that never comes), so the new page arrives as a fresh snapshot. In the Filament lab's navigation run a page went from 25 KB to 17 KB on the disk, about a third less main-thread blocking, the player jumps to any page without replaying the ones before it, and the last page before the tab closed is no longer lost when the swap was too large for the closing request. Markers, `SessionReplay.mark()` calls and console messages during the swap are kept, and the console stays patched through it, so a wrapper another script put around `console.error` stays in place. A recording now has a chunk row per page with `wire:navigate` as with page loads. Snapshots of pages reached with `wire:navigate` are not shared through `snapshots.share_routes`: only a page load is, never a page shown after a `wire:navigate`, even when recording started there.

### Fixed

- **Stylesheets that finish loading after the page was recorded are deduplicated too.** rrweb sends the text of a `<link rel="stylesheet">` that was still loading when it was serialized (a page-specific stylesheet `wire:navigate` appends, or a slow one at page load) later, as an attribute change. That text went up inline on every page view; it is now stored once by hash like every other stylesheet, and the player puts it back. Recordings made before keep playing as they are.

## 1.0.0-beta.4 — 2026-10-07

### Added

- **`on_error.livewire_error_modal`.** When a failed Livewire request puts the `on_error.ask` question up, the question can take the place of Livewire's modal with the error page: `production` (the default) does so while `app.debug` is off, where that page says no more than "500 | Server Error", and keeps the debug error page behind the question in development; `replace` always, `keep` never. When a failed request put the question up, the dialog shows the status code and the error page's title (left out when it is only the app's name, as on the debug page) under its own title and says the last action could not be completed (`recorder.ask.failed`), so nothing is lost with the modal; after "Send" a short notice thanks the person (`recorder.ask.sent`). Both strings in all five languages. An expired page (419) keeps Livewire's offer to reload. Nothing changes without `on_error.ask`.

### Fixed

- **The `on_error.ask` dialog is a native `<dialog>` in the browser's top layer.** It opens with `showModal()` one tick after the trigger, so it is centred in the viewport whatever the page does and sits above anything with a z-index, Livewire's own error modal included: a failed Livewire request used to open Livewire's error page over the question, which only showed once that page was closed. The rest of the page is inert while it is open; Escape and a `close()` from outside count as "Don't send".

## 1.0.0-beta.3 — 2026-10-07

### Added

- **Recording only when something goes wrong (`mode = on_error`).** The browser keeps the last `on_error.buffer_seconds` (60) in memory, with a fresh page snapshot every half window, and uploads nothing until a marker of a type in `on_error.triggers` (`error` and `request` by default; `console`, `rage-click` and `custom` on request) happens. Then it uploads that window and records the rest of the tab's session as usual. `mode` defaults to `session`, so nothing changes for existing apps. `SessionReplay.isBuffering()` in the browser.
- **`on_error.ask`.** After a trigger, a small dialog drawn by the recorder (plain DOM in a closed shadow root, never part of a replay) asks whether to send the replay; "Don't send" drops it and leaves the tab alone for the rest of its session. Signed-in people can send it anonymously: the `privacy.anonymous` rule for that one recording (an `anonymous` field on the upload that only ever removes identity from the signed token). Strings in `recorder.php`, in all five languages.
- **The window survives a failed upload (`on_error.keep_pending`).** The server that cannot take the upload is usually the one whose failed request fired the trigger. The first time the window's upload fails it is kept in the browser's IndexedDB, and the tab's next page load sends it first, in its original place in the recording; dropped after `idle_timeout`, when the person changes or when the tab stops. On by default; `false` keeps nothing recorded at rest in the browser. Nothing is kept before the person agreed with `on_error.ask`.
- **Shared snapshots.** Pages that look the same for everyone (a pricing page, the docs, a sign-in form) can have their snapshot stored once per SHA-256 of its content and shared by every recording, like stylesheets: opt in per route name or path with `snapshots.share_routes` and `snapshots.share_paths` (`Str::is` patterns, keyed entries read like plain ones). The chunk keeps the full snapshot event with `data.srSnapshot: <sha256>` in place of its tree; recordings without it, and pages not opted in, are stored as before. Ids a script makes up on every load (`snapshots.volatile_ids`, Filament's dropdown panels by default) are renamed in shared snapshots, so two loads of a page still match. The upload answers the same whether the snapshot was stored or not, the viewer serves one only for a recording that points at it, and `session-replay:prune` keeps it while a recording that is left does. New: the `replay_session_assets` table, `replay_assets.kind`, the `session-replay.ingest.snapshot` and `session-replay.snapshot` routes. Run `php artisan migrate` (or publish the migrations again with `run_migrations` off).

### Changed

## 1.0.0-beta.2 — 2026-10-02

### Added

- **`except_routes`.** Route names (`Str::is` patterns) that never get the recorder, next to the `except` paths. The default list leaves out the password-reset and verification pages of Laravel's starter kits (`password.*`, `verification.*`) and of Filament panels (`filament.*.auth.password-reset.*`, `filament.*.auth.email-verification.*`, `filament.*.auth.email-change-verification.*`), whatever their URL. An app that published its config before gets the default list from the package until it sets its own.
- **`privacy.anonymous`.** Records signed-in people without storing who they are: no person and no impersonator, the workspace and your properties stay. Who is signed in still decides whether a page is recorded and when a new recording starts, and uploads are limited per person through a keyed hash in the signed token that is never stored. Filament panels follow it too.
- **`privacy.store_user_agent`.** `false` drops the browser's user agent; the device class is kept.

### Changed

- **Docs.** A shorter Features list in the README and on the docs index, one line per area.

### Fixed

- **`except` with keyed entries.** A published `except` list with a keyed entry followed by a plain one (`['secrets' => 'admin/secrets*', 'billing/*']`) threw on every recorded page; keys are now ignored, in `except_routes` too.

## 1.0.0-beta.1 — 2026-10-02

First beta. Names and config may still change before 1.0; every change will be listed here with how to upgrade.

### Added

- **Recorder.** `@sessionReplay` before `</body>` records the page with rrweb 2: one recording per tab, continued across page loads until the tab sits idle (`idle_timeout`), a sticky sampling decision (`sample_rate`), `SessionReplay::recordWhen()`, `guests`, `except`, opt-in consent (`window.SessionReplay.consent(true)`), optional Global Privacy Control. A recording belongs to one person in one workspace: a tab that changes person, workspace or impersonator starts a new one, and the server refuses an upload that crosses either line.
- **Privacy defaults.** Every input masked (passwords always), `data-replay-mask`, `data-replay-block`, `data-replay-ignore`, `privacy.mask_all_text` for layout-only recordings, no IP address stored. Text typed into rich editors (`contenteditable`) is masked like an input, hidden inputs lose their value, the query parameters in `privacy.redact_query` (`token`, `signature`, `code`, `state`, `email`, …) lose their value in every URL the recorder sends (links and form actions in the page included), and the default `except` list leaves out password-reset and verification pages.
- **Markers.** Uncaught errors and unhandled rejections, `console.error`, failed Livewire requests, LCP/INP/CLS, rage clicks, page views (`wire:navigate` included) and your own (`SessionReplay.mark()`), indexed in `replay_markers` and drawn on the player's timeline. A rage click is labelled by the control that was clicked: `button "Save changes"`, never the text of a link or a cell.
- **Small recordings.** Stylesheets are stored once per SHA-256 of their content instead of inside every snapshot, attributes the player never uses (`wire:snapshot`, `wire:effects`, Alpine expressions) are dropped, comments and scripts are left out, batches are gzipped in the browser and stored and served as sent. `x-cloak` and Livewire's `wire:loading*`, `wire:offline*` and `wire:dirty*` stay, because stylesheets select on them (`size.keep_attributes` takes `prefix*` too).
- **Ingest.** Identity comes from a token signed when the page rendered (person, workspace, impersonator, properties), so the endpoint needs no session and no CSRF token; per-person throttle, batch and recording size limits, idempotent retries. Guests are throttled per rendered page (a nonce in the signed token, not a value the browser picks), `ingest.daily_mb` caps what one person uploads in a day and `ingest.guest_daily_mb` what all guests do together, only a single complete gzip stream is accepted (no second member or trailing bytes behind the checked one), and a recording only takes batches from the same person, workspace and impersonator.
- **Storage.** Gzip chunks on any filesystem disk, the index in four tables on a configurable connection, `session-replay:prune` with `retention.days` and pinned recordings.
- **Watching.** `<x-session-replay::player>` and a built-in list and player behind the `viewSessionReplay` gate, which receives the recording and guards every data route; only the local environment is let in until the app defines it. `session-replay:install` publishes the provider with the gate. The player draws the mouse as a trail that fades along its length and marks every click with a ripple and a lingering dot, on the replay's clock (frozen on pause, in step with the speed, never drawn across a seek); `--sr-pointer` sets the colour.
- **Log context.** The running recording's id and URL in Laravel's `Context`, so log lines and error reports link to the replay.
- **Cached pages.** `ingest.token_days` (7) is how long the token a page was rendered with is accepted, and `ingest.guest_tokens_expire=false` lets a token that names nobody (no person, no workspace, no impersonator) live as long as the page cache that holds it.
- **Lists that follow the gate.** `SessionReplay::visibleUsing(fn (Builder $query, $viewer) => ...)` keeps recordings the gate would refuse out of lists, in SQL; `SessionReplay::visibleTo($query)` applies it on your own page.
- **Languages.** The viewer and the player in English, German, Spanish, Romanian and Russian, following the app's locale (`vendor:publish --tag=session-replay-translations`).
- `HasSessionReplays`, `ReplaySessionStarted`, `SessionReplay::tenantUsing()`, `impersonatorUsing()`, `propertiesUsing()`, `userUsing()`, `urlUsing()`.
