# packstub/session-replay

Session replay for a Laravel app, built on rrweb: a recorder served to the browser, an ingest endpoint, gzip chunks on a filesystem disk with an index in the database, and a small gated viewer. **Session Replay for Laravel** on packstub.dev. Free, MIT. `packstub/filament-session-replay` (the sibling repo, `plugins/filament-session-replay`) puts the sessions into a Filament panel and requires this package; the two share the `Packstub\SessionReplay\` namespace (Composer merges the PSR-4 directories), so class names must not collide across them. The plan and the reasoning behind the decisions live in `workspace/notes/session-replay/plugin-idea.md`.

## Commands

```bash
composer test               # Pest suite (Testbench, in-memory SQLite, no Filament, no Livewire)
composer test:filter <name>
composer lint               # Pint
npm test                    # node --test over resources/js/lib (pure functions)
npm run build               # esbuild: resources/js -> resources/dist (committed)
composer serve              # Testbench workbench on :8000: a page to record, the viewer on /session-replay, /agent signs in Ana Support
npm run test:types          # tsc over npm/index.d.ts and npm/types.test.ts (the npm package's declarations)
npm run test:e2e            # Playwright: Assist between two Chromium browsers on the workbench (`npx playwright install chromium` once; CI runs it too)
```

## Layout

- `resources/js/core.js` — the recorder, started by `boot(config, options)`; `resources/js/recorder.js` is the directive's entry (reads `window.__sessionReplay`, `global` and `pageConfig` on), `resources/js/standalone.js` the npm package `@packstub/session-replay` (built to `npm/dist`, not committed; staged by `release.yml` through npm trusted publishing, no token, and live once a maintainer approves it with 2FA on npmjs.com; a version already on npm is skipped): fetches the config from the token route (`TokenController`, `ingest.token_endpoint`), checks it with `lib/standalone.js` (uploads only to the token route's origin; Assist, shared snapshots and a cross-origin cookie forced off), renews the token at half its life by `expires_in` on its own clock (`createTokenRefresher()` in `lib/standalone.js`: timers capped at 5 minutes, checked again on `visibilitychange`/`pageshow`/`online`, retries with backoff, one request shared with the 401 refresh; `update(config, { renewal: true })` keeps the recording as it is), a renewal that finds the person signed out or someone else ends the recording (`revoke()`; `consent(true)` waits for the next `start()`), refreshes the token once on a 401, `header()` for `X-Session-Replay`. CORS on ingest and token: `Http/Middleware/HandleReplayCors` with `Support/AllowedOrigins` (`ingest.origins`, exact origins only, never credentials on ingest). The token route also refuses a request without an Origin header that another page made (`Sec-Fetch-Site` `cross-site` or `same-site`: a tag or a link). Docs: `docs/standalone.md`; lab: `workbench/standalone`, `tests/e2e/standalone.spec.js` (records across origins; the 401 refresh, with the first upload answered 401 by `page.route`). Pest: `tests/Standalone` (session cookie) and `tests/StandaloneBearer` (a request guard standing in for `auth:sanctum`). The npm package's own files: `npm/index.d.ts`, checked by `npm run test:types` against `npm/types.test.ts` (tsc only), and `npm/README.md`, which `release.yml` copies over the README before `npm publish`.
- `resources/js/recorder.js` + `core.js` — runs on recorded pages: session id per tab in `sessionStorage` (idle timeout, sticky sampling), rrweb `record()` with the privacy options, markers (errors, console, failed Livewire requests, vitals, rage clicks, navigation, custom), batching, gzip via `CompressionStream`, upload, retry, the plain cookie the log context reads. `resources/js/lib/process.js` — the pure part: attribute stripping, stylesheet slots, asset placeholders, restore; tested with `node --test`. `resources/js/player.js` + `player.css` — loads manifest, chunks and stylesheets, mounts `rrweb-player` and the marker list on `[data-session-replay-player]`.
- `resources/dist` — the built files, committed and served by `ScriptController` under `{path}/scripts/{file}`; an app never builds or publishes anything. Rebuild after every change in `resources/js`.
- `src/SessionReplayManager.php` + `Facades\SessionReplay` — what the app registered (`recordWhen`, `userUsing`, `tenantUsing`, `impersonatorUsing`, `propertiesUsing`, `urlUsing`), `recorder()` (the script tags with the config and the signed token), `check()` (the gate rule), URLs.
- `src/Support/ContextToken` — identity for ingest: user, tenant, impersonator and properties signed with the app key when the page renders. The ingest endpoint trusts only this, so it needs no session, cookie or CSRF token.
- `src/Http/Controllers/IngestController` + `src/Support/BatchIngester` — the upload endpoints and what a batch does to the index. Events are never parsed on the server; the browser sends the index next to them ("meta"). Gzip is inflated once with a ceiling, to keep a bomb away from the viewer's browser. Stylesheets are stored under the SHA-256 of their content, verified on upload.
- `src/Support/Assist` + `Models/AssistRequest` + `Http/Controllers/AssistController` (visitor) + `AssistAgentController` (agent) — help requests (plan: `workspace/notes/session-replay/assist.md`). One row per request in both directions (`opened_by`), statuses and transitions on the model, each move one conditional UPDATE (`transition()`); `lock_key` (unique, null once finished) keeps one request per recording (without one: a hash of the token's nonce and the tab id the recorder keeps in `sessionStorage` `sr:tab`, the nonce alone for a client that sends none). Limits per workspace (`max_open_requests`), guests behind `assist.guests` with their own per-workspace budget and only from a recording with events. The claim and the proposal store `agent_type`, `agent_guard` and `agent_scope`, and `holds()` / `whereHolder()` compare all of key, type and guard wherever the holder matters (stage, agent routes, status poll, `mine`, the views) (`Holler::scope()` in the agent's request); `startCall()` runs in the visitor's request (no panel, the default guard) and loads the agent from those (`agentModel()`), passes `scope:` to `Holler::start()`, moves the status first and creates the call outside any transaction (ended again on failure); `reconcile()` in the visitor's poll ends a live request whose call is over. Holler's two words: a window **claims** its side of a call (`claim` on the poll, `Call::CLAIM_SECONDS`; the visitor's poll takes `claim`, and `callsPollCeilingMs()` keeps both sides' polls a second under it), and a person puts a call **on hold** (`on_hold`, a participant status). Assist goes along with a hold (the request stays live, the stage has Put on hold / Resume through Holler's `hold` and `resume` routes, the visitor's page says the agent will be right back), and `reconcile()` withdraws an agent whose stage stopped polling for `holdPatienceSeconds()` (Holler's `hold_timeout`, never under `reconnect_timeout`) while the assist is on hold (`letGoOfAbandonedHold()`, decided again under the call's row lock), which sends the request down the agent-left-the-live-view path; `Holler::start()` takes the caller out of every call they are in, so `claim()`, `propose()` and `startCall()` refuse while the agent is joined in another assist call (`inAnotherAssist()`; `blocked: other_assist` in the agent's view of a claimed request); `tests/Assist/AssistHoldTest.php`. The agent's pointer without control is the `point` / `point.hide` message (`Pointer` in `lib/assist-stage.js`, `ui.pointer` in `assist-ui.js`, one cursor element shared with remote control); an optional message type is named in the hello's `can` and sent only to a peer that named it (`Endpoint.peerCan()`), since an unknown `t` counts as a bad message: add new types that way, never by loosening a control message. `visibleTo()`/`queue()`: requests without a recording only while `SessionReplay::assistsWithoutRecording()` (no `visibleUsing()`, or a `canAssistUsing()`), and the workspace `SessionReplay::tenantFor()` names for the agent's request bounds them all. Claim/propose refuse `connection_mismatch` while `storage.connection` is set and `holler.connection` differs. Visitor routes are stateless like ingest (`Http/Concerns/ReadsRecorderToken`, shared with `IngestController`: the token, the triple to create, re-bind or answer a knock, the request's secret after); agent routes sit behind the viewer middleware and gate and ask `visibleUsing()` and `SessionReplay::canAssist()` on every call. The timeouts run inside the polls (`expire()`, `sweep()`). Everything about `packstub/holler` is behind `Assist::callsAvailable()` (class exists, context bound, `assist.calls`); the call is created when the page acknowledges a claim or accepts an offer (`startCall()`, kind `assist`, guest id `guest:<request id>`), the visitor's poll proxies `Holler::poll()`, a `CallEnded` listener ends the request (`callOver()`), except when Holler dropped the agent's side while the guest was still joined: then the request goes back to `claimed` with `call_id` null and `claimed_at` now (`rejoining()`: claimed with a `started_at`; `reconnecting` in both presentations), and the visitor's poll creates a new call only while `agentPresent()` (the stage's status poll bumped `agent_seen_at` within `AGENT_PRESENT_SECONDS` and after the drop); the claim lapses after `claim_timeout_seconds`, `started_at` is kept (max_duration, the marker), `AssistStarted` is not sent again. `sweep()` runs at most every `SWEEP_EVERY_SECONDS` per workspace (`Cache::add`), `queue($agent, $workspace)` narrows the query. The visitor routes take a recording without a `write_key` as no recording (no heartbeat bump, no attach or re-bind, no knock). The server writes the `assist` marker when a request finishes (at the recording's clock from its last chunk, with per-grant durations); a browser cannot send one. Off by default (`assist.enabled`; the routes register at boot). The visitor's page: `lib/assist-hook.js` (in the recorder: the tab id, the heartbeat, the knock from the upload answer, the `tap()` at the end of `emit()` before the async stylesheet dedupe, the `SessionReplay.assist` stub; it `import()`s the module from `config.assist.module` only when an offer knocks, a request is stored, the button is on or `request()` is called), `resources/js/assist.js` (the bundle entry, built as a separate ES module, `resources/dist/assist.js`, served by `ScriptController`: hands the engine, `AssistClient` and `drain`, to `lib/assist-visitor.js`, which never imports `@packstub/holler` so the node tests run without `node_modules`; `installAssist()` takes what the recorder lends; the request id and secret in `sessionStorage` `sr:assist`; polls on a Web Worker timer; a `CallClient` subclass with `media: 'none'` and the `assist` channel), `resources/js/assist-ui.js` (closed shadow root on a `data-replay-skip` host: panel, prompts, cursor, outline, annotation canvas), `lib/assist-protocol.js` (the channel protocol both sides share: hello, parts, backpressure, schemas, `LiveStyles`), `lib/assist-signaling.js` (the engine's signaling interface over the visitor routes, all POSTs, credentials in the body), `lib/assist-control.js` (the remote control executor: passwords also once shown as text, nothing off-screen, hidden or inside skip/block regions). Consent on the visitor's page: one prompt per kind at a time, a 10 s cool-down after a no (`ask()` in `lib/assist-visitor.js`), prompts that focus the card and take no press for 500 ms (`assist-ui.js`), the microphone muted by two flags (the visitor's, which only their button clears, and the agent's `media.stop`, which only a fresh Allow clears); `installAssist(recorder, env)` takes the engine (`env.Client`, `env.drain`) and fakes for the tests (`tests/assist-visitor.test.js` drives it against a real protocol endpoint, `tests/assist-ui.test.js` the prompts on a small fake DOM). The hook imports the module only from the page's origin (`sameOrigin()`). `skipNodes()` in `lib/process.js` drops `data-replay-skip` subtrees. Tests: `resources/js/tests/assist.test.js` with fake channels, fetch and DOM, `assist-hook.test.js` for the lazy loading. The agent's side, in the built-in viewer: the Live tab (`ViewerController::index`, `?live=1`, `ReplaySession::live()` and `lastSeenSeconds()`, "last seen N s ago" in `viewer/partials/last-seen`), Offer help (`viewer/partials/offer-help`, on the list and the player page: the propose form, or the agent's own request's stage, or what is going), Claim and propose forms redirect to the stage when Holler is available (`hasStage()`), and the stage (`AssistAgentController::stage`, route `session-replay.assist.stage` under `viewer.enabled`, holder only, `viewer/stage.blade.php` with a `data-config` JSON from `stageConfig()`: the request, the agent routes, Holler's routes by `assist.calls_routes` (null when not registered: the stage says so), video, labels `viewer.stage.*`). `resources/js/stage.js` + `stage.css` (built to `resources/dist/stage.*`, served by `ScriptController`) mount on `[data-session-replay-stage]`: rrweb's `Replayer` from `@rrweb/replay` in live mode, its own `AssistClient` (`lib/assist-client.js`, shared with `assist.js`: the worker-timer poll loop from `lib/worker-timers.js`; a client on a call the request no longer has is dropped for the new one) over `HttpSignaling` with `kind: 'assist'`, the protocol `Endpoint` attached synchronously in `datachannel` (only for the peer `guest:<request id>`), the status route polled every 2 s, the overlay (pointer → control messages, wheel and keys → scroll, a click on a field opens an editor box → `focus`/`input`/`select`), the ink canvas, the audio bar. `lib/assist-stage.js` is the DOM-free part, tested in `tests/assist-stage.test.js`: `LiveFeed` (clock offset on the first event, stylesheets restored and capped per channel, Meta kept until the first full snapshot, a new Replayer per channel), `stageStop()` (over, or `mine` false), the agent's `Endpoint` with `AGENT_RATE` (closes `too_fast`), `stagePoint`/`stageDelta` (mapPoint on the live iframe, never the row's viewport columns), `Gesture`, `editable`, `AgentState` (what the visitor's messages mean, `why()` for every disabled control), `handleVisitorMessage`. Typing on the visitor's page reaches the mirror when the field changes (`size.sampling.input` `last`), live as stored. Pest: `tests/Assist/AssistStageTest.php`. End to end: `tests/e2e/assist.spec.js` with `playwright.config.js` (fake media flags, `PHP_CLI_SERVER_WORKERS=8`, a SQLite file and cache of its own in a temporary directory, migrated fresh, so `composer serve`'s database is never touched; the workbench turns Assist and the button on, registers Holler's provider and `Holler::routes()` when Holler is installed, SQLite in WAL with a busy timeout); the visitor's panel is a closed shadow root, so the test forces `attachShadow` to `open` with an init script. Recorder size: measure `resources/dist/recorder.js` after a change in the hook (131.5 KB, 43 KB gzipped on 2026-11-24 with the token renewal; 129.9 KB on 2026-10-28; 125.4 KB before Assist). The engine comes from the `@packstub/holler` dev dependency (npm, `^1.0`), bundled into `resources/dist`.
- `src/Support/ReplayStorage` — paths and bytes on the disk (`sessions/{id}/{seq}.json.gz`, `assets/{aa}/{hash}.css.gz`).
- `src/Http/Middleware/AuthorizeViewer` — the `viewSessionReplay` gate on every viewer **and data** route, with the recording as argument when there is one; `ReplayDataController` (manifest, chunk, stylesheet), `ViewerController` (list, player page), `resources/views`.
- `src/Http/Middleware/AddReplayContext` — global middleware: recording id and viewer URL into Laravel's `Context`.
- `src/Models` — `ReplaySession`, `ReplayChunk`, `ReplayMarker`, `ReplayAsset` on `storage.connection`; `Concerns/HasSessionReplays`; `Events/ReplaySessionStarted`; `Commands/PruneCommand`.
- `stubs/SessionReplayServiceProvider.stub` — published by `session-replay:install` with the gate in it.
- `workbench/` — the Testbench app behind `composer serve`.
- `docs/` — customer docs; synced into the store under `session-replay/1.x` once the package is public (no docs-sync workflow until then).

## Conventions

- PHP 8.3+, Laravel 12 and 13. Every change needs a test and a `CHANGELOG.md` line.
- Changelog headings are `## <version> — <date>`; the tag is `v<version>` on `main`. The section becomes the GitHub release and `release.yml` appends GitHub's list of merged pull requests under it, so keep it short and human: an optional lead sentence, then at most about six one-line bullets saying what a user gets, in plain words (class or method names only when a user needs the name, never lists of them). Always keep breaking changes with an `**Upgrading:**` line, security or privacy fixes, new minimum PHP/Laravel versions and migrations to run; leave out CI, tests and refactors.
- Nothing here may import from `Filament\` or `Livewire\`; what needs a panel belongs in `packstub/filament-session-replay`. The recorder may *detect* Livewire in the browser.
- Privacy defaults only ever get stricter inside a major. Every privacy control stays in this free package.
- Strings live in `resources/lang/{en,de,es,ro,ru}/viewer.php` and `player.php` (`session-replay::viewer.*`); the player gets its strings from the Blade component as `data-labels`. A new string goes into all five languages; `ViewerTest` compares the key sets.
- The gate guards data, not pages: any new route that returns recording content goes behind `AuthorizeViewer` with the recording bound.
- Never add identity to the ingest request other than the signed token; never key a limit by IP (edge proxies hide it).
- Config keys, migration file names, route names, the chunk format and the `/*sr-asset:<sha256>*/` placeholder are shared with the Filament package and with stored recordings; they must not change inside a major. Schema changes follow the workspace rule (final shape in `create_*`, guarded `add_*`).
- Tests that need `packstub/holler` live in `tests/Assist` (`AssistTestCase` boots Holler when it is installed). `packstub/holler` `^1.0` is in `require-dev` (and only suggested to apps), so they run everywhere; `needsCalls()` still skips them in an install without it. To try a local Holler change, add a path repository to `../holler` for the run without committing it.
- After a change here run the Filament package's suite too (`plugins/filament-session-replay`, `composer test`).
- After a change in `resources/js`, run the Filament package's browser check too: `cd ../filament-session-replay/workbench/lab && RECORDER=$PWD/../../../session-replay/resources/dist/recorder.js node navigate.mjs` (excluded pages, swaps, identity changes across `wire:navigate`; `CHANNEL=chrome` uses the installed Chrome). Unit tests cover the state machine, not the browser.
